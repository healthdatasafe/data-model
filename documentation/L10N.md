# Translations

The definitions carry `en` and `fr` (both required where a schema says so), and nothing else. Every text of another
locale is in `definitions/l10n/{locale}.json` and is added to the published files by the build (`src/l10n.js`).
Consumers read the same files: a text map simply has more keys.

```json
{ "items.json": { "body-weight/label": { "en": "Body weight", "text": "Peso", "reviewedBy": "…", "reviewedOn": "2026-12-01" } } }
{ "items.json": { "body-weight/label": { "en": "Body weight", "text": "Peso", "status": "draft" } } }
```

- **Where a new text goes:** `en` and `fr` in the definitions; `es`, `it`, `pt-BR`, `de` in `definitions/l10n/{locale}.json`,
  where each entry carries its review mark. A text in the definitions carries none, so the build refuses a text of any
  other locale there (`checkInlineLocales`, 4.56.2) and names each one by locale, published file and path, the key its
  entry takes in the locale file. Until 4.56.1 a few were written in the definitions: `es` on eight items, two streams
  and the `lab-result` and `professional-role` vocabularies, `de` and `it` on the document-kind labels. 4.56.2 moved
  them to `es.json`, `de.json` and `it.json` as drafts, with the same texts.
- **Locales:** six full locales, `en`, `fr`, `es`, `it`, `pt-BR`, `de` (4.56.0). `pt` (European) would be the seventh
  and goes to files loaded on demand (§ Size). The added locales are the ones hds-lib supports (`localizeText.ts`), and
  `de`, which hds-lib does not offer yet: the SMART consent screen of the cores shows it (hds-fhir-js extension options
  carry every language of a label).
- **German is Swiss Standard German** (`ss`, never `ß`; formal *Sie*; Swiss clinical terms where they differ: Austritt,
  Zuweisung, Spital), read in Germany and Austria too. A `de-DE` variant, if ever needed, is a separate locale.
- **Reviewed or marked draft** (decision of 2026-11-25). A text is reviewed (`reviewedBy`, `reviewedOn`) or a draft
  (`"status": "draft"`, no reviewer; a machine draft, say). Any other shape fails the build. A reviewed text replaces the
  draft in the same entry.
- **A text map does not mark drafts:** `{ "en": …, "it": … }` reads the same, draft or reviewed. The mark is per locale, in
  `pack.json` `"l10n": { "<locale>": { "status": "draft" | "reviewed" } }`, for the locales of `definitions/l10n` only:
  `draft` when one of its published texts is a draft. A reader that shows the texts to a third party or on a consent
  screen reads it there.
- **The build fails** on a text whose English changed, a path or a published file that does not exist, an empty text, a
  text of a locale other than `en` and `fr` in the definitions, two array entries with one value or id, an unknown
  locale. To change an English text, change or delete
  its translations in the same commit. It also fails on a stream whose consent-screen label (its only active item's, else
  its own) has no text in a locale of `definitions/l10n` (`checkConsentLabelLocales`, 4.56.1): a new stream or item that
  names a consent row brings its es, it, pt-BR and de texts in the same commit. A label held in `do-not-translate.json`
  is exempt until its official wording is added.
- **Not translated for now:** `datasources.json` (the search-service labels and descriptions, technical texts) and the
  eventType `extras` unit names (`eventTypes.json` `extras/*/name`). They stay `en` (and `fr` where written); whether
  to translate them is an open decision (B-2026-11-28-6).
- **`do-not-translate.json`**: `[{ "file", "path", "reason" }]`, texts of licensed or validated instruments. A translation
  of one is reviewed, never a draft, and needs `"official": "<source>"`.
- **Path:** the published file name, then object keys joined with `/` (`~1` for `/`, `~0` for `~`); an array entry is
  `[value=<JSON>]` or `[id=<JSON>]` when it has one, else `[index]`.
- **Converter packs are frozen** (AGENTS.md § Versions): their texts are published in `converters/{key}/l10n-{locale}.json`
  (`{ locale, status, packs: { "pack-v1.json": { "<path>": "text" } } }`, `status` that of the locale in `pack.json`), which
  may change. hds-lib 2.70.0 and later read it (`converters.loadTexts()`). A new converter version has no block until one
  is added: copy the previous pack's block under the new file name, or its texts stay English (the build does not warn).
- **Checked again after the merge:** item, vocabulary and document-kind schemas, document-kind labels unique per language,
  stream labels distinct on a consent screen.
- **Version:** a new locale is a minor, a corrected translation a patch.
- **Size:** a locale adds about 90 KB to `pack.json` (20 KB gzip); with `de`, 1.84 MB raw, 241 KB gzip (4.56.0). At 2 MB
  raw, 300 KB gzip or a seventh locale, new locales go to files loaded on demand instead.
